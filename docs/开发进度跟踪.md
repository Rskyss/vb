## 这个仓库为什么需要台账

skill 自己写着"聊天记录会丢、只有项目里的文档算数""用户不读 commit"，但它自己前 11 个提交全靠 commit 消息记录——**没吃自己的狗粮**（2026-08-01 用户点出）。

对规则仓库来说这个缺口尤其要命：**每条规则的来历比规则本身更值钱**。规则都是拿真实教训换来的，不知道它当初为什么立，就不知道能不能改、该不该守，后人（包括下个会话的 AI）很容易把用血换来的约束当成累赘删掉。

## 2026-08-01 与真实项目对齐：补 6 项缺失能力 + 5 条新教训

**状态：⏳ 已落盘，待下次真实开发中检验**

起因：用户在真实项目里发现 skill "能力不如项目自己的 CLAUDE.md"，要求对表补齐。做法是把该项目的规则逐条拆成条目，跟 skill 现有内容对照，缺什么补什么（不凭记忆，用脚本逐条查覆盖）。

### 一、补齐 6 项缺失能力（对表查出）

| 能力 | 补之前的状态 |
|---|---|
| 三段版本号 `v大版本.功能版.修复号` ＋ 判断三问 | 只有一句"每个里程碑 +0.1"，说不清什么时候该动哪一段 |
| 切 `v1.0` 的六个条件 | 只有"上线那天切 v1.0"，没有判断标准 |
| 不跳号、不倒退 | 缺 |
| 修订号只用数字、禁止字母 | 缺（`v0.91.a` 在业界指发布**前**的 alpha，与"发布后的补丁"含义正相反） |
| 文档先行：**开工前**先读台账 | 只有"完工后登记"这一半 |
| **借用外部流程时台账仍是唯一权威** | 完全没有——而这是真实项目摔了三次才定下的规矩 |

最后一条最关键：项目里常同时装着别的流程工具（结构化施工框架、规划助手等），它们自带 spec/plan 产出，与本规范的台账**目的重叠、极易互相顶替**，真实案例是走了另一套流程就以为它的产物算记录了，台账漏登记、用户失去进度视野。补进 SKILL.md 关卡④，含"设计一批准立刻建文档并登记进行中、不等编码完成""外部工具的 spec 改成指向本规范文档的指针"等归位规则。

### 二、补 5 条新教训（来自当天一次真实排查）

1. **不发版＝不推主干**——原规则只写了"发版时怎么推"，没堵住"不发版能不能推"，这个空白被钻过两次（用户说"不单独发版"，AI 理解成"可以单独推一个非版本提交"），两次都得改写历史收拾。配套给出"要跑 CI 就推临时分支"的正道——第二次被钻正是这个需求逼的。
2. **外部质疑先核实再认**——真实案例：外部 AI 判定一份报告"财务数据是硬伤"，逐条核对官方财报后发现是它自己错了（拿第一季度数据反驳第二季度财报）；若当场认错去改，等于把对的数据改成错的。但对方论据全错不等于怀疑没价值——顺着它的方向复查，确实查出三条自己的真问题。
3. **修完代码默认不清洗存量数据**——清洗要重跑大量 AI 调用、烧真实额度，收益取决于"老数据还有没有人看"。真实案例：某缺陷修复后 AI 自动批量重跑几十份历史产物，用户叫停"现在没什么流量，改老的有必要吗"。规矩：默认不洗；要洗先报成本等拍板；已获批范围中途变大要再问。
4. **批量核查数据时判据要先验准**——判据本身就是被测对象。真实案例：判据改了三版才对，第一版漏检 6 份、第二版把正确的误判为错。清单：正反样本各验一遍、抽 3–5 条人工读、报数字时说清判据。
5. **修完要用同一套判据复测**——别默认"改了代码就一定好了"，那次修完重跑，13 份里仍有 1 份没修好，正是复测才发现。

### 三、新增可复制资产（assets/）

- **`pre-push`** — git 推送拦截器，拒绝一切标题不是 `vX.Y ` 开头的提交推向主干。**这是本次最重要的产出**：前两次犯错都是读着同一份文档犯的，证明文档挡不住理解偏差，必须上机械拦截。已在真实项目实测：`docs:` 提交被拦下、`v0.99 …` 放行、推临时分支不受限。
- **`全局规则模板.md`** — 全局 AI 协作规则（`~/.claude/CLAUDE.md`）的可移植副本。那个文件每次对话都加载，但躺在本机用户目录、不跟任何仓库走，换机器就没了。**已剔除**与个人密钥、密钥路径相关的段落（本仓库公开），并做了敏感内容扫描。

### 四、新增 `references/换机器搬家清单.md`

用户诉求是"换机器装上 skill 就能用"，但实测发现光装 skill 不够，还有三样长在原机器上：全局规则、推送拦截开关（`core.hooksPath` 是本机 git 配置，不跟仓库也不跟 skill）、项目记忆（且项目路径一变就读不到）。清单给出四步操作 + 装完自检的四项验证。

## 2026-11-05 ✅ v0.3 加流程守卫：不再只靠 AI 自觉走流程

起因：用户查问超级助手改版有没有走本规范。核查发现 AI 只在开头加载过一次 skill，之后漏了独立复查、真实环境走查、文档同步，还在用户只是提问时直接改了代码。记录里没有“这步不走”的判断，是漏了，不是流程有问题。用户要求先解决 Claude 这边不再漏。

做法：
- 全局规则 `~/.claude/CLAUDE.md` 和 `assets/全局规则模板.md` 新增“开发流程：一律走 vibe-workflow”，并写明和 6A 冲突时以本规范为准
- 新增 `assets/vibe-guard.py`，接入 `~/.claude/settings.json`：用户每发一条消息，提醒走流程；这一轮改了代码，结束前拦一次，要求核对关卡；台账没更新要先更新
- 只看这一轮开始之后的改动，包括已提交的；后台子代理没结束时不结束这一轮，等它汇报后再核对；用户打断不会冲掉没核对的改动；还没纳入版本管理的生成文件不算，已纳入的照算；只拦一次不循环；第二次仍没更新台账，直接提示用户
- 换机器搬家清单加第 5 步和自检项；SKILL.md、README 的资产列表同步

替用户拍板的决定：① 对所有用 git 的项目生效；② 只改 `docs/` 下的文档不拦；③ 用 AI 工具的提醒和回合结束检查，不用 git 提交时检查，因为这次长期没提交，那样不会触发。

自测：`tests/test_vibe_guard.py` 23 项，新增项都先失败后全过；用实际安装路径在临时项目走了闲聊和改代码两种情况。

独立复查第一轮不通过，查出 8 条。最严重：脚本文件不在时，提醒命令会让用户每条消息都发不出去；已改成命令自身兜底放行。还修了：打断会冲掉未核对的改动、同一轮提交后不拦、生成文件被当代码、非 UTF-8 环境失效。

第二轮复查仍不通过，查出后台子代理的改动会漏拦、残留开始时间让闲聊被拦、已跟踪的 build 文件被漏掉，以及一项测试依赖本机配置，均已修。第三轮查出开着开发服务器时每轮闲聊都被拦，已改成只等子代理。第四轮守卫部分通过，只补了已知限制。上线后在真实对话里已确认：每条消息收到提醒，改了代码结束前被拦下。

已知限制：只认当前项目文件夹，改了别的文件夹里的文件看不到；没提交的删除、改名和子模块内的改动不计入；已提交的删除、改名和只改提交说明会计入；开轮后 1 秒内完成的提交不计入；同一时间别的工具或会话改的文件分不出来，会被算进这一轮，闲聊被打断后用户自己改文件也会多拦一次；只排除常见生成文件，`.coverage`、`target/`、`.next/` 这类没被忽略时仍算代码；子代理以外的后台任务（Bash、工作流、队友）改的文件可能漏拦；`background_tasks` 字段依据官方文档，未在真实后台任务上实测；只管 Claude Code，Codex、Gemini、Cursor 不受这个守卫约束；提醒能保证出现，不能保证 AI 照做。

未做：Codex 的本地副本仍是旧版；三个规则洞尚未写进 SKILL.md 正文，目前在全局规则和提醒里。

版本判定：现在你可以让 Claude 改了代码却没登记时被自动拦下，是新能力，定为 v0.3。用户 2026-11-05 同意推送。
