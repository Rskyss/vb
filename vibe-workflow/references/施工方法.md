# 施工方法 —— 关卡②的完整作业规程

对齐（或大需求走完规划流程）之后怎么动手。核心思想：**小步施工、每步留证、有人复查**——就算 AI 单干，也要像一个"施工员+质检员"的两人班组那样工作。

## 一、先测后码（每个任务的标准动作）

顺序固定，不许颠倒：

1. **先写一个会失败的测试**——用测试把"这个任务做完应该是什么样"钉死
2. **跑一遍，亲眼看它失败**——失败证明测试真的在把关（一上来就通过的测试什么都没测）
3. **写最少量的代码让它通过**——不顺手多做、不"既然打开了就重构一下"
4. **跑一遍，亲眼看它通过**，再跑全量测试确认没改坏别处
5. **小步提交**——每个任务完成即提交一次，出问题能精确退回

为什么不许"先写完代码再补测试"：补出来的测试是照着已有代码写的，代码错它也跟着错，等于自己给自己批改还提前看了答案。

**项目没有测试体系？** 给本次改动搭最小的测试能力（够验证这个任务即可），并在台账里写明"本项目测试体系从 X 任务起建立"。不许以"项目没有测试"为由跳过。

## 二、按清单逐个来，不许并做

- 有任务清单（规划流程产出）就严格按依赖顺序执行；没有清单的小任务，先在心里拆成"能独立验证的最小步"
- **一次只做一个任务**：做完 → 验证 → 台账/清单上勾掉 → 才开始下一个
- 严禁"这几个任务差不多，一起写完一起测"——一起写完意味着出了错分不清是哪一步引入的

## 三、做完先自审，再找"外人"复查

每个任务完成后两道检查：

**自审（自己做）**：对照任务的验收标准逐条核对；重读自己的改动，找"顺手多做的""偷懒少做的""硬编码的临时值"。

**复查（换双眼睛）**：
- 你的工具支持派子代理/新开代理会话（如 Claude Code 的 Task/Agent 功能）→ 派一个**没有参与施工的新代理**审查：给它任务要求和改动内容，让它独立回答两个问题——"要求的都做到了吗？有没有做多？"和"代码质量有没有问题？"发现的问题修完再复查一遍，通过才算过
- 工具不支持子代理 → 退而求其次：完成任务后**新起一段独立检查**，假装自己是第一次看这份改动的陌生审查员，只看"要求 vs 实际改动"，不看施工过程的记忆。效果打折，但比不查强

为什么自审不能代替复查：施工者对自己的成果天然盲视——写的时候想岔了，检查的时候会顺着同一个岔路再想一遍。

## 四、被复查揪出问题时的规矩

- 复查提的问题先核实再改：它说得对就改，说得不对就说明理由——**不许为了让复查通过而假装接受**，也不许没验证就照单全收
- 改完必须重新过一遍复查，不许"我改好了"就自行销案

## 五、卡住了怎么办

同一个问题连试两次没解决：**停止原地重试**。第三次尝试前必须换方法——重新读报错原文、缩小复现范围、检查最近一次能工作的版本和现在差了什么。三次仍不行，如实告诉用户卡在哪、试过什么，不许硬憋。

## 红线

- 代码写在测试前面 → 删掉重来，按顺序走
- "测试太简单没必要" → 简单代码也会错，写测试 30 秒，漏 bug 半天
- 复查一次没过就绕过复查直接进下一个任务 → 回去
- 台账/清单没勾就开始下一个任务 → 回去补
