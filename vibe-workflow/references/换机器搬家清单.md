# 换机器 / 重装环境：搬家清单

装上本 skill 只恢复了**方法论**。还有几样东西长在原来那台机器上、不跟着仓库走，照下面逐项办。

## 一、必做四步

### 1. 装 skill 本体

把本仓库的 `vibe-workflow/` 目录放进 `~/.claude/skills/`：

```bash
git clone <本仓库地址> ~/tmp-vb && cp -r ~/tmp-vb/vibe-workflow ~/.claude/skills/
```

装完在 Claude Code 里能看到 `vibe-workflow` 出现在可用 skill 列表里。

### 2. 恢复全局规则

把 `assets/全局规则模板.md` 的正文（说明头之后的部分）拷进 `~/.claude/CLAUDE.md`。

这份是**每次对话都加载**的规则（沟通口径、中断询问的时机、给非技术用户讲话的方式），不是按需加载的 skill —— 少了它，AI 的说话方式和判断习惯就变回默认的了。

> 注意：原文件里与个人密钥、密钥路径相关的段落**不在**这份副本中（本仓库公开）。那部分需要另行单独配置，本清单不涉及。

### 3. 每个项目启用推送拦截

在每个用本规范的项目里各做一次：

```bash
mkdir -p .githooks
cp ~/.claude/skills/vibe-workflow/assets/pre-push .githooks/
chmod +x .githooks/pre-push
git config core.hooksPath .githooks
```

**为什么每台机器、每个项目都要单独做**：`core.hooksPath` 是本机的 git 配置，既不跟着仓库走、也不跟着 skill 走。`.githooks/pre-push` 文件本身可以提交进仓库（推荐），但那行 `git config` 命令换台机器就得重新执行一次，否则 hook 文件在、却不生效。

验证是否真的生效：

```bash
git commit --allow-empty -m "docs: 测试"
git push --dry-run origin main     # 应当被拦下并打印说明
git reset --hard HEAD^             # 删掉测试提交
```

### 4. 搬项目记忆

AI 记住的用户偏好、服务器登录方式、历史决策，存在：

```
~/.claude/projects/<项目路径编码>/memory/
```

`<项目路径编码>` 是项目绝对路径把 `/` 换成 `-`，例如 `/Users/你/Desktop/project/myapp` → `-Users-你-Desktop-project-myapp`。

**两个坑**：
- 换机器要手动拷这个目录，否则 AI 会失忆
- **项目在新机器上的路径若和旧机器不同，目录名对不上，记忆同样读不到** —— 要么把项目放在相同路径下，要么把目录改名成新路径对应的编码

## 二、装完自检

在新机器上开一轮对话，逐条确认：

- [ ] 问 AI「我们的版本发布规则是什么」——答得出"一个版本＝远端恰好一个提交"
- [ ] 造一个 `docs:` 空提交试推主干——被 hook 拦下
- [ ] 问 AI「这个项目的服务器怎么登录 / 之前定过什么规矩」——答得出（记忆搬对了）
- [ ] 让 AI 做件小事——它说话是产品语言而非技术术语，且不说奉承话（全局规则生效）

四条都过，环境才算恢复完整。

## 三、心里有数

| 东西 | 在哪 | 换机器 |
|---|---|---|
| 工作流方法论 | 本 skill 仓库 | ✅ clone + 拷进 skills 目录 |
| 项目自己的规矩（CLAUDE.md） | 各项目仓库里 | ✅ clone 就有 |
| 全局规则 | `~/.claude/CLAUDE.md` | ⚠️ 照第 2 步恢复 |
| 推送拦截开关 | 本机 git 配置 | ⚠️ 每个项目照第 3 步执行一次 |
| 项目记忆 | `~/.claude/projects/…/memory/` | ⚠️ 照第 4 步拷，注意路径一致 |
| 个人密钥类配置 | 本机私密目录 | ⚠️ 不在本仓库，另行处理 |
