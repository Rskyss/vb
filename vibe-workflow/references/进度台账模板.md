# 进度台账模板

项目里没有 `docs/开发进度跟踪.md` 时，接到第一个任务就按此结构创建。**这份文档的读者是不懂代码的用户**，所有内容用产品语言写。

## 初始结构

```markdown
# 开发进度跟踪

> 本文档是项目的总台账：每个任务一条记录，只追加不删除。
> 状态图例：🔄 进行中 / ⏳ 自测通过待验收 / ✅ 已完成

## 版本记录

- （发布第一个版本后从这里开始记，最新的在上面）

## 任务记录

（最新的任务在上面）
```

## 单个任务的登记格式

```markdown
### YYYY-MM-DD 任务名（用户能看懂的叫法）

**状态：⏳ 自测通过待验收**

- **需求**：用户原话或大白话复述
- **用户拍板的口径**：动工前问过的问题和用户的答案，逐条列出（这是将来"当初为什么这么做"的唯一依据）
- **实现**：做了什么，用产品语言描述用户能感知的变化
- **自测**：怎么测的、测了什么、结果如何（真实环境走流程的证据，不是"测试通过"四个字）
- **已声明的边界/遗留**：做不到的、暂不做的、已知的小问题
```

## 登记规则

1. 任务开始时就登记一条 🔄，不要等做完才补——用户随时打开要能看到"现在在干什么"
2. 用户验收通过后改 ✅ 并注明日期；如果发布了版本，注明版本号和链接
3. 同一任务的后续小修正，在原条目下追加加粗要点，不另开条目
4. 版本发布后在「版本记录」区加一行：版本号、日期、一句话说明这版用户能感知到什么变化、Release 链接

## 写法对照

| ❌ 不要这样写 | ✅ 要这样写 |
|---|---|
| 新增 `/api/export` 接口，前端调用后返回 blob | 报表页新增"导出Excel"按钮，点击下载当前筛选结果 |
| 修复 token 刷新竞态 | 修复"偶尔登录不上"：现在登录状态到期会自动续期，用户无感 |
| 重构 service 层依赖注入 | （纯内部整理、用户无感知的改动，写：内部代码整理，用户无变化，为后续 XX 功能铺路）|
