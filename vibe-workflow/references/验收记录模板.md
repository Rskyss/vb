# 验收记录模板

台账（开发进度跟踪.md）记"发生了什么"，验收记录记"凭什么算做完"。较大的任务建议单独一份验收文档（如 `docs/任务名/ACCEPTANCE_任务名.md`），小任务直接把下面内容并入台账条目即可。

## 结构

```markdown
## 任务名（YYYY-MM-DD，状态）

一句话说明这个任务交付了什么。

- **口径（用户拍板）**：动工前确认的关键决定，逐条列出
- **实现**：改了哪几块，各自让用户感知到什么变化（产品语言）
- **自测**：按自测清单逐项的结果——
  - 自动化测试：X 项全过（新增 Y 项）
  - 真实环境流程：谁的身份、走了什么流程、看到什么结果
  - 权限矩阵：验证了哪些"不该能做的确实做不了"
  - 清理：测试产生的账号/数据/配置已删除还原，列明细
- **已声明的边界**：做不到的、暂不做的、已知小问题（写在这里的才算"已声明"，用户没看到的不算）
- **用户验收**：日期 + 用户确认方式（真机试用/看截图/口头确认）+ 验收期提出的修正及落地情况
```

## 规则

1. 状态流转：自测通过 ⏳ → 用户验收 ✅。自测没全绿不能进入"待验收"
2. 用户验收期提出的修正，落地后追加记录在同一节，不新开
3. 验收通过后如果发版本，注明版本号
4. "用户没提出异议"不等于"验收通过"——要拿到明确的确认
